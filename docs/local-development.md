# Local development

## Requirements

| Tool | Version | Notes |
| --- | --- | --- |
| Node.js | 22 or newer | The repo is developed on Node 24; CI uses 22. |
| npm | 10+ | Ships with Node. |
| Git | any recent | — |

Supabase and Docker are **not** required for local work. Without credentials the app runs on a JSON store.

## Setup

```bash
git clone https://github.com/0xMudit/the-bureaucracy.git
cd the-bureaucracy
npm install
cp .env.example .env.local
npm run seed
npm run dev
```

Open <http://localhost:3000>.

`npm run seed` fetches every feed, keeps the last 24 hours, writes `data/seed.json` (committed demo data) and
`.data/store.json` (your local mutable store). Votes and comments then survive restarts.

If you only want to regenerate the committed demo file:

```bash
npm run seed -- --file-only
```

## Environment variables

Everything is optional for local-only work. `.env.example` is the annotated reference.

| Variable | Required | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | production | Supabase project URL. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | production | Public key used for sign-in sessions. Safe in the browser. |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | optional | Newer publishable key; used when the anon key is absent. |
| `SUPABASE_SERVICE_ROLE_KEY` | production | Server-only key. Never prefix with `NEXT_PUBLIC_`. |
| `CRON_SECRET` | production | Bearer token for `POST /api/ingest`. Generate with `openssl rand -hex 32`. |
| `NEXT_PUBLIC_SITE_URL` | recommended | Canonical URL for metadata, sitemap and RSS. |
| `ADMIN_EMAILS` | optional | Comma-separated addresses that always resolve to `admin`. |
| `SUPABASE_ACCESS_TOKEN` | optional | Management API token for `npm run auth:email`. Not read at runtime. |
| `SMTP_HOST` … `SMTP_SENDER_NAME` | optional | Custom SMTP forwarded to Supabase by `npm run auth:email`. |

## The three store modes

`lib/store.ts` chooses a backend at request time:

| Mode | When | Behaviour |
| --- | --- | --- |
| `supabase` | URL + service-role key set | Production. Service role, server-side only. |
| `local` | No Supabase, `.data/` writable | JSON file store; votes, comments and submissions persist. |
| `readonly` | No Supabase, no writable `.data/` | Serves `data/seed.json`; writes are refused, feed empties after 24 h. |

## Scripts

```bash
npm run dev          # dev server (Turbopack)
npm run build        # production build
npm start            # serve the build
npm run typecheck    # tsc --noEmit
npm run check        # typecheck + build (CI)
npm run seed         # ingest + write seed file + local store (+ Supabase if configured)
npm run db:push      # apply supabase/migrations to the linked project
npm run db:reset     # reset the local Supabase database and replay migrations
```

Auth helpers (`auth:email`, `auth:admins`, `auth:doctor`) are covered in [supabase.md](supabase.md).

## Common problems

**The wire is empty.** Stories are filtered to the last 24 hours and `data/seed.json` ages out. Run
`npm run seed`.

**Feeds fail behind a proxy or a firewall.** Ingestion is plain `fetch` over HTTPS. Check
`npm run seed` output for per-feed errors; one failing source does not stop the others.

**Votes or comments reset.** You are probably in `readonly` mode: `.data/` is missing or not writable, or
Supabase is half-configured (URL set, key missing). Check `storeMode()` in `lib/store.ts`.

**Auth redirects to localhost in production.** `NEXT_PUBLIC_SITE_URL` must be the production origin. The
Supabase redirect allow-list must contain it too; see [supabase.md](supabase.md).

**Sign-up works but login is refused.** Email confirmation is on. Open the link, or check the address in the
Supabase dashboard. `npm run auth:doctor` reports unconfirmed and profile-less users.

**`next-env.d.ts` keeps changing.** It is generated by `next dev` and gitignored; leave it alone.
